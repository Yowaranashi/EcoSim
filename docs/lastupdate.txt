EcoSim: описание файлов проекта и функций
=========================================

Дата обновления: 2026-05-10
Файл документации: docs/lastupdate.txt

Примечание: в запросе было написано dock/lastupdate.txt. В проекте уже используется каталог docs/, поэтому файл создан как docs/lastupdate.txt.


1. Верхний уровень проекта
--------------------------

Файл: CMakeLists.txt
Назначение: описывает сборку проекта CMake.
Что делает:
  - задает C++17;
  - включает тестирование;
  - собирает библиотеку ecosim_models;
  - собирает библиотеку ecosim_core;
  - собирает recorder_csv как shared library и recorder_csv_static для тестов;
  - собирает executable ecosim;
  - собирает executable ecosim_integration_tests;
  - регистрирует CTest-тест ecosim_integration_tests;
  - описывает install и CPack package.
Функций C++ нет.
Входные данные: CMake cache/options, исходные файлы проекта.
Выходные данные: build targets, install/package targets.

Файл: README.md
Назначение: пользовательская документация.
Что делает:
  - объясняет сборку;
  - объясняет запуск;
  - объясняет тесты;
  - описывает консольные команды;
  - описывает app.toml и scenario.toml;
  - описывает schedule-команды и CSV.
Функций C++ нет.
Входные данные: текстовая документация.
Выходные данные: справка для пользователя.

Файл: LICENSE
Назначение: лицензия проекта.
Функций C++ нет.


2. src/main.cpp
---------------

Назначение: точка входа приложения.

Функции:
  - int main(int argc, char** argv)
    Вход:
      - argc: количество аргументов командной строки;
      - argv: массив аргументов. argv[1], если задан, используется как путь к app TOML.
    Выход:
      - 0 при успешном запуске и завершении;
      - 1 при ошибке initialize/startModules.
    Эффект:
      - создает Logger;
      - создает Application;
      - вызывает initialize(config_path);
      - вызывает startModules();
      - запускает console или headless режим;
      - вызывает shutdown().


3. src/core/app.h и src/core/app.cpp
------------------------------------

Назначение: верхний объект приложения и владелец главных подсистем.

Класс: ecosim::Application

Функции:
  - Application(Logger& logger)
    Вход: logger.
    Выход: объект Application.
    Эффект: создает EventBus, AppConfig, ModuleRegistry, ModuleContext, ModuleManager, Console.

  - ~Application()
    Вход: нет.
    Выход: нет.
    Эффект: очищает EventBus, чтобы подписчики не переживали выгрузку модулей.

  - bool initialize(const std::string& config_path)
    Вход: путь к app TOML.
    Выход: true/false.
    Эффект: загружает AppConfig, загружает manifests, регистрирует core factories, строит модули, регистрирует консольные команды.

  - bool startModules()
    Вход: нет.
    Выход: true/false.
    Эффект: запускает модули через ModuleManager.

  - void runHeadless()
    Вход: нет.
    Выход: нет.
    Эффект: выполняет deterministic tick-loop:
      1. onPreTick для всех модулей;
      2. onTick для всех модулей;
      3. onPostTick для всех модулей;
      4. EventBus::deliverBuffered();
      5. onDeliverBufferedEvents для всех модулей;
      6. проверка shouldStop и max_ticks.

  - void runConsoleLoop()
    Вход: stdin.
    Выход: нет.
    Эффект: читает строки консоли и передает их в Console::execute().

  - void shutdown()
    Вход: нет.
    Выход: нет.
    Эффект: останавливает модули.

  - ModuleManager& moduleManager()
    Вход: нет.
    Выход: ссылка на ModuleManager.

  - ModuleRegistry& registry()
    Вход: нет.
    Выход: ссылка на ModuleRegistry.

  - EventBus& eventBus()
    Вход: нет.
    Выход: ссылка на EventBus.

  - const AppConfig& config() const
    Вход: нет.
    Выход: read-only AppConfig.

  - Console& console()
    Вход: нет.
    Выход: ссылка на Console.

  - void registerCoreCommands()
    Вход: нет.
    Выход: нет.
    Эффект: регистрирует help, module.list, module.start, module.stop, scenario.list, sim.run, sim.sensitivity, sim.pause, sim.resume, ogre.status, ogre.enable, ogre.disable, sys.quit.


4. src/core/config.h и src/core/config.cpp
------------------------------------------

Назначение: TOML-like загрузчик app-конфигов, manifests и сценариев.

Структуры:
  - ModuleManifest: type_id, version, dependencies, criticality, library_path.
  - ModuleInstanceConfig: type_id, instance_id, enabled, params.
  - AppConfig: mode, error_policy, instances, modules_dir, scenario_path, output_dir, dt, max_ticks.

Функции публичного API:
  - static AppConfig ConfigLoader::loadAppConfig(const std::string& path)
    Вход: путь к app TOML.
    Выход: AppConfig.
    Эффект: читает mode, error_policy, modules_dir, scenario_path, output_dir, dt, max_ticks, instances.

  - static ModuleManifest ConfigLoader::loadManifest(const std::string& path)
    Вход: путь к manifest.toml.
    Выход: ModuleManifest.
    Эффект: читает type_id, version, dependencies, criticality, library_path.

  - static ScenarioConfig ConfigLoader::loadScenario(const std::string& path)
    Вход: путь к scenario TOML.
    Выход: ScenarioConfig.
    Эффект: читает legacy и новый формат сценария, проверяет model_id и integrator.

  - Criticality parseCriticality(const std::string& value)
    Вход: строка criticality.
    Выход: Criticality.
    Эффект: преобразует строку в enum.

Основные внутренние функции config.cpp:
  - readFile(path)
    Вход: путь.
    Выход: содержимое файла.

  - trim(value)
    Вход: строка.
    Выход: строка без пробелов по краям.

  - stripQuotes(value)
    Вход: строка.
    Выход: строка без внешних кавычек.

  - findRawValue(content, key)
    Вход: текст TOML, имя ключа.
    Выход: optional raw value.

  - parseArrayStrings(value)
    Вход: TOML array строк.
    Выход: vector<string>.

  - parseArrayNumbers(value)
    Вход: TOML array чисел.
    Выход: vector<double>.

  - parseNumberMap(value)
    Вход: inline map string->number.
    Выход: map<string,double>.

  - parseMatrix(value)
    Вход: TOML matrix.
    Выход: vector<vector<double>>.

  - parseArrayOfTables(value)
    Вход: TOML array of inline tables.
    Выход: vector<map<string,string>>.

  - parseNumberTable(content, table_name)
    Вход: TOML text, имя таблицы.
    Выход: map<string,double>.

  - mergeQualifiedNumberMap(target, prefix, values)
    Вход: target map, prefix, map values.
    Выход: нет.
    Эффект: пишет prefix.name -> value.

  - isSupportedIntegrator(integrator)
    Вход: строка.
    Выход: true для euler/rk4.

28. Основные runtime-потоки данных
----------------------------------

App config:
  app.toml -> ConfigLoader::loadAppConfig -> AppConfig -> Application/ModuleManager.

Scenario:
  scenario.toml -> ConfigLoader::loadScenario -> ScenarioConfig -> ScenarioTimeline -> ScenarioRunner.

Модель:
  ScenarioConfig.model -> createModelDynamics(model_id) -> IModelDynamics::configure -> SimulationWorld::dynamics_.

Tick:
  Application::runHeadless -> module.onPreTick -> module.onTick -> module.onPostTick -> EventBus::deliverBuffered.

World event:
  SimulationWorld::emitTickEvent -> EventBus::emit -> RecorderCsv::handleEvent после deliverBuffered.

CSV:
  SimulationEvent world.tick -> RecorderCsv::initializeCsvHeader/buildCsvRow -> output/simulation.csv.
